# Owner-Controlled Final Deployment and Android Checklist

These instructions never require sharing secrets in a chat. They are prerequisites for a live site or APK; **no account has been accessed or configured in this source delivery**.

## 1. Complete local build preflight on a networked PC

Install Node.js 22.13+; extract the project. From project root:

```bash
npm install
npm --prefix backend install
npm run typecheck
npm run build
npm run check:backend
npm run test:backend
npm test
npx playwright install chromium
npm run test:e2e
npm run scan:secrets
```

Fix errors. Commit the *genuine* root and backend `package-lock.json` files generated by `npm install`. Then use `npm ci` and `npm --prefix backend ci` for reproducible CI/release. Do not handwrite fake lockfiles.

## 2. Secure Google/Groq setup

In Google Cloud Console, create a project, enable Gmail API, configure OAuth consent (Testing mode if appropriate) and an OAuth **web app** redirect URL exactly matching `https://YOUR_HOST/api/auth/google/callback`. Restrict the Gmail account to the exact owner address. Set credentials directly in private backend environment / cloud secret configuration, never in GitHub, frontend or APK. Understand restricted Gmail scope and testing refresh-token expiry/verification restrictions.

In GroqCloud create a **new** private key, configure `GROQ_API_KEY`, `GROQ_MODEL`, `AI_ENABLED=true`. Verify the model with `npm --prefix backend run check:groq`. Connect Gmail and separately opt in to external AI processing in app Settings. Automatic AI review requires a *second*, distinct opt-in and a daily draft cap.

## 3. Persistent VM/cloud setup

The current Node/Express + `node:sqlite` architecture is **not** a drop-in Cloudflare Workers app. Choose an eligible VM with persistent encrypted storage (Oracle Always Free is a possible but not guaranteed choice). Attach only a durable disk. Configure a real hostname/domain, TLS (Caddy), firewall, backups, service health monitoring and secure SSH. See `docs/MODULE4_DEPLOYMENT.md` for Docker Compose and OAuth HTTPS instructions.

After deploying the app with one persistent Node instance, configure **either**:

- `MONITOR_INTERNAL_TIMER_ENABLED=true` and `MONITOR_POLL_INTERVAL_MS=900000` on the continuously running remote VM; Cloudflare Cron is optional, OR
- an authenticated HTTPS scheduler trigger using Cloudflare Cron with `MONITOR_WORKER_ENABLED=true` and a secret. The scheduler is merely a relay; the real backend and database must remain online. AI processing may exceed the relay's request timeout, so the internal VM timer is preferable for automatic AI triage.

Do not run independent concurrent schedulers without coordinating ownership and locks. Verify the `GET /api/health` URL, persistence after server restart and a successful heartbeat in Settings. Then power off your local PC and confirm two or more *real* cloud-triggered Gmail checks; source code alone is not evidence.

## 4. Secure Gmail end-to-end test (owner-controlled only)

Use a **test Gmail account you control**, connect/reconnect, inspect message metadata, search sender, verify Reply-To and thread, create a test draft and edit it. Check version/attachment hashes. **Approve the precise test recipient/content yourself** and verify the Gmail API returns an ID and the item appears in Sent. Reject and duplicate-send cases must never send. Do not test real sending without explicit approval of that exact test email.

## 5. Push, web and Android

Configure Firebase Cloud Messaging in your own Firebase project. Firebase public browser configuration goes into the frontend deployment; service-account credentials remain private server secrets. Register browser notifications and test a generic push; confirm its click opens Inbox or Approval Center. Confirm only minimal safe metadata appears on the lock screen.

Deploy the web PWA before Android. In `android/gradle.properties` set a real host. Install Android Studio, SDK 35 and Gradle with compatible JDK. Create a private signing key and publish a verified `/.well-known/assetlinks.json` for the package `ai.lifepilot.app` with the correct certificate fingerprint. Build and test a debug APK on a controlled device; test OAuth login, voice permission denial, typed fallback, deep links, background notifications, stale draft handling and logout. Only sign/release an APK after all checks pass. TWA needs the online PWA; it is **not** an independently offline Gmail application.

## 6. Cost and operational limitations

- Oracle Cloud Always Free compute: eligible capacity and continued availability are **not guaranteed**; provider may require account/payment verification and reclaim idle instances. Check [Oracle official Always Free resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm).
- Cloudflare Workers Free Cron: currently documents five cron triggers per free account and 100,000 daily requests across Workers, with CPU and runtime limits; see [official limits](https://developers.cloudflare.com/workers/platform/limits/). This is optional if using the single-VM timer.
- Firebase Cloud Messaging is currently categorized as no-cost in [official Firebase pricing](https://firebase.google.com/pricing). Device delivery depends on permissions and OS/browser behavior.
- A domain name, paid cloud overages, Google restricted-scope OAuth verification/security assessments, Groq usage and Android Play publication may involve conditions or costs. **Do not promise free forever or ignore billing settings.**

## 7. Evidence required before public portfolio release

Record accessible HTTPS website/API URLs, verified CI run, real-test Gmail logs with sensitive data removed, Groq model and tier, PC-off scheduler timestamps, FCM device delivery and notification screenshot, signed APK build output, Android device test results, consent screenshot, release tag and an explicit limitations section. Without that evidence, label the project a **software engineering integration prototype**, not a deployed production product.
